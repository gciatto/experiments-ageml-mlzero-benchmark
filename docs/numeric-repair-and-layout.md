# MLZero numeric correction and canonical campaign layout

This bundle targets the actual v5 filesystem inventory supplied on 19 November
2026, not a fresh installation. Run only after stopping the launcher. The script
checks the checkout lock and active systemd search scopes before moving data.
It performs no package install and no API call until all local tests and checks
have passed and the user enters their key for the resumed campaign.

## Single entry point

Extract at /root/experiments-ageml-mlzero-benchmark, then inside tmux:

```bash
bash scripts/repair-and-resume.sh
```

The entry point runs 18 local tests, migrates existing artifacts and starts only
the original Gemini 2.5 campaign config. The original local runtime must match its
recorded package/source hashes apart from the known Gemini text adapter variant;
unknown differences abort. Do not regenerate runtime.json or reinstall packages.

## Result policy

- All 30 final classification outcomes from Gemini 2.5 remain, including the
  seven genuine no_artifact outcomes. They are not retried until success.
- All previously started regression searches (all three regression datasets)
  are moved to artifacts/diagnostics/campaign-layout, with their source code,
  generated models, raw logs and original records. Both successful and failed
  searches are treated equally because their search paths were exposed to the
  faulty regression gate. The next Gemini 2.5 run starts Ames repetition 1 with
  the corrected validation, not the middle of an affected search.
- All three completed Adult 3.1 attempts and all actual artifacts are relocated
  to mlzero-gemini-31-flash-lite-hamlet-cv-s42-1h-local-factory-v5. The previous
  manually copied Adult summary and interrupted Adult repetition 4 are archived.
- No active directory, config or runtime filename needs the old correction
  suffix. Historical logs and frozen source identities retain their original
  contents. The migration does not forge run IDs, change stored model code,
  alter model hashes, or relabel an unselected artifact as a winner.
- The two ORIGINAL configs remain the entry points. The shared launcher activates
  each model's recorded adapter automatically, verifies runtime provenance and
  skips final dataset/repetition outcomes from before the relocation. No concurrent
  campaigns in the shared runtime are allowed.

## Numeric correction

The node evaluator originally computed regression RMSE in the prediction dtype,
which can be float32. The export verifier reread predictions in float64. The
old rtol=1e-10 rejected two real Ames exports with fold-level differences around
1e-8 relative. The corrected verifier keeps float64 recomputation authoritative
and uses regression-only rtol=1e-6, atol=1e-8 to compare the legacy reported
numbers. This is approximately eight float32 epsilons of relative error and is
not a model-quality acceptance threshold. Classification keeps rtol/atol=1e-10.

No data/fold/evaluator/factory checksum checks are removed. Unknown class labels,
wrong/missing/duplicate OOF IDs, incomplete or nonfinite fold scores and material
metric mismatches are rejected. The claimed mean must also match the arithmetic
mean of its claimed folds. The return value used for selection is the recomputed
float64 metric; MCTS still maximizes negative RMSE. The node evaluator and all
frozen dataset contracts stay unchanged, so existing input hashes remain valid.
The verifier source hash is recorded by the v5 invocation identity and pinned
by artifacts/campaign-layout.json for subsequent canonical launches.

## Later continuation with Gemini 3.1

After the 2.5 launcher finishes or is stopped, inside tmux:

```bash
unset GEMINI_API_KEY AGEML_BENCH_PILOT
bash scripts/run-local-hamlet-cv.sh configs/gemini31-hamlet-cv-local-factory-v5.yml
```

Adult 1-3 are skipped. Adult 4 restarts from the beginning. The helper uses the
actual original run IDs and never invents compatible hashes. Normal 45-run
reporting is regenerated by the existing native report function at completion.

## Verification and limits

18 offline tests pass: full filesystem migration of the supplied duplicate
summary layout, preservation of selected model bytes, skipped completed original
identities, diagnostic archival of successful and failed pre-fix regressions,
reapplication preserving post-fix results, float32 and float64 score exports,
strict classification comparison and rejection of altered scores, sources, fold
assignments, missing rows and nonfinite/partial CV. Python compilation and Bash
syntax checks pass. The installer repeats these tests in the user's .venv.
No paid model calls or live container modifications have been made in preparing
this bundle. A new generated MLZero candidate may still have legitimate code,
installation or training errors; this repair does not rewrite such candidates.
